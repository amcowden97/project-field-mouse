# Security Policy

## Supported versions

Security fixes are evaluated for the latest published release candidate and the current
default branch. Older snapshots and archived release artifacts are retained for history
and are not maintained independently.

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability. Use GitHub's **Security** tab
and **Report a vulnerability** workflow when private vulnerability reporting is
available. If that workflow is unavailable, contact the repository owner privately
through GitHub before sharing technical details.

Include the affected version, impact, reproduction conditions, and any suggested
mitigation. Remove credentials, precise station coordinates, recordings, and personal
data. Maintainers will acknowledge the report, assess severity, coordinate a fix, and
credit reporters who wish to be acknowledged.

Operational incidents without a security impact belong in the bug template after logs
and health output have been sanitized.
